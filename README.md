# ESP32-CAM QR Reader → UART

Проект для платы **ESP32-CAM** (в Arduino IDE выбрана плата **ESP32 Dev Module**): распознавание QR-кодов камерой и передача результата в UART. Реализована защита от дублирования событий: пока QR-код не изменился и находится в кадре, данные повторно не отправляются. Новый QR (даже идентичный предыдущему) отправляется только после того, как предыдущий код был уверенно убран из кадра.

## Функциональность

- Распознавание QR-кодов через камеру ESP32-CAM (OV2640).
- Передача payload в UART (`Serial`, 115200 бод) в формате:

  ```text
  QR_DATA: <payload>
  ```

- **Антидребезг / антидубль:**
  - Пока QR виден в кадре — повторной отправки нет.
  - Если QR не распознаётся **5 кадров подряд** (`MISSING_THRESHOLD = 5`), считается, что код убран из кадра, и взводится флаг готовности (`isQrArmed = true`) к приёму нового QR.
  - Если после этого показать **точно такой же** QR — он будет отправлен снова (это новое появление кода в кадре).
  - Логика реализована в отдельной задаче FreeRTOS (`onQrCodeTask`), запущенной на ядре 1.

## Аппаратные требования

- ESP32-модуль **с PSRAM** (обязательно — библиотека использует `ps_malloc`).
- Камера OV2640 (протестировано).
- Модель камеры в коде: `CAMERA_MODEL_AI_THINKER`.
- Плата в Arduino IDE: **ESP32 Dev Module**.

> Без PSRAM библиотека работать не будет. Убедитесь, что у вашей платы ESP32-CAM PSRAM присутствует (AI-Thinker — да).

## Программные требования

- **Arduino IDE 2.x**.
- Ядро ESP32 — **3.3.8** (в данном проекте откат ядра не выполнялся).
- Библиотека **ESP32QRCodeReader** — форк, адаптированный под Arduino IDE (см. раздел «Ключевые особенности компиляции»). Версия в `library.properties`: `1.1.0`.
- Зависимости библиотеки (внутренние): модифицированный Quirc + код из OpenMV/MaixPy.

## Структура проекта (логические модули)

Код разбит на модули для удобства чтения:

1. **Конфигурация и глобальные переменные** — порог `MISSING_THRESHOLD`, счётчик `missingCounter`, флаг `isQrArmed`, `lastPayload`, `isCurrentCodeSent`.
2. **Отправка в UART** — `sendUartData()` (легко заменить формат вывода).
3. **Основная задача сканирования** — `onQrCodeTask()`: приём кадра, проверка валидности, фильтрация дублей, сброс/взвод флага готовности.
4. **Setup** — инициализация `Serial`, `reader.setup()`, `reader.beginOnCore(1)`, создание задачи.
5. **Loop** — пустой (вся работа в задаче).

## Ключевые особенности для нормальной компиляции

Именно эти шаги потребовались, чтобы проект собрался и заработал. Без них компиляция падала с ошибками `implicit declaration of function 'ps_malloc'` и сопутствующими.

### 1. Форк библиотеки, адаптированный под Arduino IDE

Используется форк `ESP32QRCodeReader`, адаптированный для установки через Arduino IDE (оригинал от Alvaro Viebrantz рассчитан в первую очередь на PlatformIO). В README форка прямо указано: *«This fork is adapted to work on Arduino IDE»*. Версия `library.properties` — `1.1.0`.

### 2. Ручное исправление заголовков в двух файлах библиотеки

Даже с форком потребовалось вручную добавить недостающие `#include` в исходники библиотеки (иначе ядро 3.3.8 не видит объявлений `ps_malloc`, `free`, `memcpy` и т.п.).

**Файл `src/openmv/collections.c`** — в начало файла добавлено:

```c
#include <stdlib.h>
#include <string.h>
#include <stdbool.h>
#include <stddef.h>
#include "esp32-hal-psram.h"
```

**Файл `src/quirc/decode.c`** — аналогично добавлены недостающие заголовки, включая `#include "esp32-hal-psram.h"` (чтобы `ps_malloc` была объявлена).

Причина: в ядре ESP32 3.x изменилась структура заголовочных файлов, а `esp32-hal-psram.h` сам по себе не подтягивает `<stdbool.h>` / `<stddef.h>`. Поэтому важен порядок включения: сначала стандартные заголовки, затем `esp32-hal-psram.h`.

### 3. Flash Mode = DIO (вместо QIO)

В Arduino IDE: **Инструменты → Flash Mode → DIO**.

Без этого плата уходила в циклическую перезагрузку с ошибками:

```text
E (31) qio_mode: Failed to set QIE bit, not enabling QIO mode
assert failed: __esp_system_init_fn_init_flash startup_funcs.c:118 (flash_ret == ESP_OK)
```

Смена режима на DIO устранила проблему.

### 4. Очистка кэша Arduino IDE (желательно, но не обязательно)

Удаление папки кэша эскизов `C:\Users\<user>\AppData\Local\arduino\sketches\` помогает гарантировать, что правки исходников библиотеки будут пересобраны. В данном проекте выполнялось, но не является строго обязательным — при чистой пересборке IDE и так подхватит изменения.

### 5. Что НЕ потребовалось

- Откат ядра ESP32 до 2.x — не выполнялся. Проект собран на ядре 3.3.8.
- Полное стирание Flash перед прошивкой — не выполнялось (опция **Erase All Flash Before Sketch Upload** оставалась выключенной).

## Формат вывода UART

Пример вывода в мониторе порта:

```text
QR_DATA: 12345
QR_DATA: HELLO-123
QR_DATA: 2026-11-26
QR_DATA: Hello, QR world!
QR_DATA: https://example.com
QR_DATA: Привет, это QR-код
QR_DATA: Заказ №7729
QR_DATA: Дата: 2026-11-26
QR_DATA: Статус: готов
QR_DATA: https://site.com/product?id=12345&color=blue&v=2
QR_DATA: {"id": 999, "status": "ok", "ts": "2026-11-26"}
```

Многострочные payload (например, «Заказ №7729 / Дата / Статус») выводятся несколькими строками — это особенность исходного содержимого QR, а не кода.

## Пустые строки в мониторе порта

Пустые строки — это служебный вывод библиотеки/ядра ESP32, а не результат работы пользовательского кода. На приёмной стороне рекомендуется фильтровать строки: обрабатывать только те, что начинаются с `QR_DATA:`.

## Настройка фильтрации

В коде:

```cpp
const int MISSING_THRESHOLD = 5; // кадров подряд без QR → считаем, что код убран
```

Увеличьте значение, если камера часто «теряет» код при плохом освещении; уменьшите, если нужно быстрее реагировать на убирание кода.
